## 三、方案一：Railway 部署（推荐）

### 步骤 1：准备代码

确保代码已推送到 GitHub。

```bash
git push origin main
```

### 步骤 2：注册 Railway

1. 打开 https://railway.app
2. 点击「Start a New Project」
3. 选择「Deploy from GitHub repo」
4. 授权 Railway 访问你的 GitHub
5. 选择 `paygo-platform` 仓库

### 步骤 3：添加 PostgreSQL

1. 在项目页面，点击「+ New」→「Database」→「PostgreSQL」
2. Railway 自动创建 PostgreSQL 实例
3. 记下连接信息（自动注入为环境变量 `DATABASE_URL`）

### 步骤 4：添加 Redis

1. 点击「+ New」→「Database」→「Redis」
2. Railway 自动创建 Redis 实例
3. 连接信息自动注入为 `REDIS_URL`

### 步骤 5：配置环境变量

在 Railway 项目 → Variables 中添加：

```
SECRET_KEY_MASTER_KEY=<生成一个 Fernet key>
JWT_SECRET_KEY=<生成一个随机字符串>
```

生成密钥命令：
```bash
python3 -c "
import base64, os, secrets
print('SECRET_KEY_MASTER_KEY=' + base64.urlsafe_b64encode(os.urandom(32)).decode())
print('JWT_SECRET_KEY=' + secrets.token_hex(32))
"
```

### 步骤 6：配置部署

Railway 自动检测 Dockerfile，无需额外配置。

如需自定义启动命令，在 Settings 中设置：
```
Start Command: uvicorn app.main:app --host 0.0.0.0 --port $PORT
```

### 步骤 7：生成域名

1. 在项目 → Settings → Networking
2. 点击「Generate Domain」
3. 获得 `https://xxx.up.railway.app` 域名

### 步骤 8：验证部署

1. 访问 `https://你的域名.up.railway.app/login`
2. 使用 `admin / admin123` 登录
3. 确认仪表盘正常显示

```bash
# API 健康检查
curl https://你的域名.up.railway.app/api/v1/health
# 返回 {"status":"ok","version":"1.0.0"}
```

## 五、方案三：Docker Compose 自托管（VPS）

适用：已有 VPS（AWS EC2 / 阿里云 ECS / 腾讯云 / DigitalOcean）

### 步骤 1：准备 VPS

```bash
# SSH 登录 VPS
ssh root@你的服务器IP

# 安装 Docker
curl -fsSL https://get.docker.com | sh
# 安装 Docker Compose
apt install docker-compose -y  # Debian/Ubuntu
# 或
yum install docker-compose -y  # CentOS
```

### 步骤 2：克隆代码

```bash
git clone https://github.com/zhizhengqin/paygo-platform.git
cd paygo-platform
```

### 步骤 3：生成密钥

```bash
python3 -c "
import base64, os, secrets
print('SECRET_KEY_MASTER_KEY=' + base64.urlsafe_b64encode(os.urandom(32)).decode())
print('JWT_SECRET_KEY=' + secrets.token_hex(32))
"
```

### 步骤 4：创建 .env 文件

```bash
cat > .env << 'EOF'
SECRET_KEY_MASTER_KEY=<上一步生成的 Fernet key>
JWT_SECRET_KEY=<上一步生成的 JWT key>
DB_PASSWORD=<你的数据库密码>
EOF
```

### 步骤 5：启动服务

```bash
# 构建并启动
docker compose up -d --build

# 查看状态
docker compose ps

# 查看日志
docker compose logs -f app

# 健康检查
curl http://localhost:8000/api/v1/health
```

### 步骤 6：配置防火墙

```bash
# 只开放必要端口
ufw allow 22    # SSH
ufw allow 80    # HTTP（如需 Nginx 反向代理）
ufw allow 443   # HTTPS
# 不要直接暴露 8000 端口！使用 Nginx 反向代理
```

### 步骤 7：配置 Nginx 反向代理（可选但推荐）

```bash
apt install nginx certbot python3-certbot-nginx -y
```

创建 `/etc/nginx/sites-available/paygo`：

```nginx
server {
    listen 80;
    server_name 你的域名.com;

    location / {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    client_max_body_size 10M;
}
```

```bash
ln -s /etc/nginx/sites-available/paygo /etc/nginx/sites-enabled/
nginx -t && systemctl reload nginx
```

### 步骤 8：配置 HTTPS（Let's Encrypt）

```bash
certbot --nginx -d 你的域名.com
```

## 八、安全加固建议

### 8.1 生产环境必须修改

| 项目 | 默认值 | 修改方式 |
|:---|:---|:---|
| 管理员密码 | admin123（bcrypt 哈希） | 设置 `ADMIN_PASSWORD_HASH` 环境变量 |
| JWT 密钥 | 硬编码默认值 | 设置 `JWT_SECRET_KEY` 强随机值 |
| Fernet 密钥 | 自动生成 | 设置 `SECRET_KEY_MASTER_KEY` 并持久化 |
| 数据库密码 | PaygoDB2026! | 设置 `DB_PASSWORD` 环境变量 |

### 8.2 生成安全密钥

```bash
# Fernet 密钥
python3 -c "import base64,os;print(base64.urlsafe_b64encode(os.urandom(32)).decode())"

# JWT 密钥  
python3 -c "import secrets;print(secrets.token_hex(32))"

# 管理员密码哈希
python3 -c "import bcrypt;print(bcrypt.hashpw(b'你的密码',bcrypt.gensalt()).decode())"
```

### 8.3 建议但不强制

- [ ] 启用 PostgreSQL SSL 连接（`?sslmode=require`）
- [ ] 启用 Redis AUTH 密码
- [ ] 配置 WAF（Railway/Render 内置）
- [ ] 设置自动备份（PostgreSQL 每日快照）
- [ ] 配置监控告警（CPU > 80% / 内存 > 85% 通知）

## 九、故障排查

### 问题 1：启动后访问 502

```bash
# 检查应用日志
docker compose logs app --tail 50

# 常见原因：
# - DATABASE_URL 格式错误（缺少 +asyncpg）
# - REDIS_URL 不可达
# - SECRET_KEY_MASTER_KEY 未设置
```

### 问题 2：仪表盘图表不显示

浏览器控制台检查 ECharts CDN 是否加载成功。如 CDN 被墙，修改 `templates/dashboard.html` 中的 CDN 地址。

### 问题 3：设备密钥无法解密

检查 `SECRET_KEY_MASTER_KEY` 环境变量是否与创建客户时使用的密钥一致。不一致会导致所有已创建的设备密钥无法解密。

### 问题 4：数据库迁移未执行

首次启动时 lifespan 自动执行 `Base.metadata.create_all` + ALTER TABLE 迁移。如果表未创建，检查日志中的 SQL 错误。

## 十一、升级迭代后如何发布

### 11.1 常规升级流程

```
1. 本地开发 + 测试通过（pytest tests/ -v，200 tests）
2. git add + git commit + git push origin main
3. 云端自动部署（Railway/Render 检测到 push 自动重新构建）
4. 验证健康检查：curl https://域名/api/v1/health
5. 浏览器验证关键功能
```

### 11.2 涉及数据库变更的升级

如果新增了表或字段：

```bash
# 1. 本地先验证迁移脚本（main.py lifespan 中的 ALTER TABLE）
# 2. 推送代码
git push origin main

# 3. 云端重新部署后，首次启动自动执行：
#    - Base.metadata.create_all（新建表）
#    - ALTER TABLE ADD COLUMN IF NOT EXISTS（新增字段）
#    - 种子数据（幂等，已存在则跳过）

# 4. 验证
curl https://域名/api/v1/health
```

### 11.3 涉及种子数据变更的升级

```bash
# 云端 Shell 中执行：
PYTHONPATH="." python scripts/seed_demo_data.py
```

**注意**：种子脚本使用 `drop_all` + `create_all`，会**清空所有数据**重新加载。生产环境慎用。

### 11.4 回滚策略

```bash
# Railway / Render：在 Dashboard 中回滚到上一个部署
# 或本地回滚后重新推送：
git revert HEAD --no-edit
git push origin main

# Docker Compose 自托管：
git pull  # 拉取回滚后的代码
docker compose down && docker compose up -d --build
```

### 11.5 加密密钥注意事项（重要）

**升级前务必确认**：`SECRET_KEY_MASTER_KEY` 环境变量在所有环境（本地、测试、生产）保持一致，否则：

- ❌ 所有已创建客户的设备密钥无法解密
- ❌ 模拟支付全部失败（Token 生成依赖原始密钥）
- ❌ 需要删除所有客户数据重新创建

**首次部署时就应固定密钥**，后续升级不改动。详见 `docs/项目文档/加密解密机制说明.md`。
