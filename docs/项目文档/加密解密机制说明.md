# 加密解密机制说明

## 一、为什么需要加密

这个平台管理着太阳能设备的**激活密钥**（secret_key）。每个设备出厂时都有一个独一无二的 32 位 hex 密钥，就像一把"物理钥匙"。平台用这把钥匙生成 9 位 OpenPAYGO Token，客户把 Token 输入设备后，设备验证通过才能供电。

如果这把钥匙在数据库里**明文存储**，一旦数据库泄露，攻击者就能：
- 无限生成 Token，免费给任何设备解锁
- 伪造 Token 让设备误以为已付款

所以必须加密存储。

## 二、用到的加密技术

### 2.1 bcrypt — 加密管理员密码

**是什么**：bcrypt 是一种"单向"哈希算法。你把密码放进去，它吐出一串乱码。这串乱码**永远无法反推出原始密码**。

**用在哪里**：
```
管理员登录 → 输入密码 "admin123"
                ↓
         bcrypt.hash(密码) → 和数据库里存的哈希值比对
                ↓
          匹配？→ 登录成功
          不匹配？→ 拒绝
```

**代码位置**：`app/security.py` 的 `hash_password()` 和 `verify_password()`

**特点**：
- 单向不可逆，即使数据库泄露也拿不到原始密码
- 每次生成的哈希都不一样（自动加盐），防止彩虹表攻击
- 验证速度故意慢（0.3秒），防止暴力破解

### 2.2 Fernet — 加密设备密钥

**是什么**：Fernet 是一种"双向"对称加密。用同一个密钥可以加密也可以解密。就像一个带密码的保险箱——有密码能打开，没密码打不开。

**为什么不用 bcrypt**：设备密钥必须能解密。生成 Token 时，平台需要用原始 32 位 hex 密钥来计算。bcrypt 是单向的，加密后就拿不回来了。

**用在哪里**：
```
创建客户 → 输入设备密钥 "a1b2c3d4..."
                ↓
         Fernet.encrypt(密钥) → 密文存数据库
                ↓
         用户模拟支付 → 平台需要生成 Token
                ↓
         从数据库取密文 → Fernet.decrypt(密文) → 还原密钥
                ↓
         用还原的密钥计算 OpenPAYGO Token
```

**代码位置**：`app/security.py` 的 `encrypt_secret()` 和 `decrypt_secret()`

## 三、SECRET_KEY_MASTER_KEY 是什么

`SECRET_KEY_MASTER_KEY` 就是 Fernet 加密解密用的**那同一个密码**（主密钥）。

可以理解为一把"万能钥匙"：
- **加密时**：用这把钥匙把设备密钥锁进保险箱
- **解密时**：用这把钥匙打开保险箱，取出设备密钥

### 3.1 密钥长什么样

一个合法的 Fernet 密钥是一个 44 字符的 base64 字符串，例如：

```
nbN-L3VnttBXL-4sB1z9QLIl9nXBvX0SJoTTxZcWdUM=
```

### 3.2 怎么生成的

启动时 `app/security.py` 的 `init_fernet()` 函数：

```python
# 优先级 1：读环境变量
key = os.getenv("SECRET_KEY_MASTER_KEY")    # 从环境变量读取

# 优先级 2：从 .env 文件读取（settings.py 启动时加载）
# （已在环境变量中）

# 优先级 3：自动生成
if not key:
    key = base64.urlsafe_b64encode(os.urandom(32)).decode()  # 随机生成
    _persist_fernet_key(key)  # 写入 .env 文件
```

### 3.3 存储在哪里

```
项目根目录/.env 文件：
SECRET_KEY_MASTER_KEY=nbN-L3VnttBXL-4sB1z9QLIl9nXBvX0SJoTTxZcWdUM=
```

`.env` 在 `.gitignore` 中，不会提交到 GitHub。云部署时通过 Railway/Render 的环境变量面板注入。

## 四、完整数据流

用一个具体例子串联整个过程：

### 4.1 创建客户时

```
操作员输入设备密钥: "a1b2c3d4e5f6a7b8c9d0e1f2a3b4c5d6"
                         ↓
        Fernet.encrypt(密钥, master_key)
                         ↓
        得到密文: "gAAAAABqDYOCr34M--FnEpJeMiRWXzk7..."
                         ↓
        存入数据库 customers.secret_key_encrypted 列
```

数据库里存的是密文，谁也看不懂。

### 4.2 生成 Token 时

```
客户要还款 → 平台需要生成 Token
                         ↓
        从数据库读密文: "gAAAAABqDYOC..."
                         ↓
        Fernet.decrypt(密文, master_key)
                         ↓
        还原出原始密钥: "a1b2c3d4e5f6a7b8c9d0e1f2a3b4c5d6"
                         ↓
        OpenPAYGO.generate_token(原始密钥, count=3, days=30)
                         ↓
        9位Token: "023554141" → 发给客户
```

## 五、不同加密的职责分工

| 加密对象 | 算法 | 类型 | 能否解密 | 存哪里 |
|:---|:---|:---|:---|:---|
| 管理员密码 | bcrypt | 单向哈希 | ❌ 不能 | `ADMIN_PASSWORD_HASH` 环境变量或代码默认值 |
| 设备密钥 | Fernet (AES-128) | 对称加密 | ✅ 能 | `customers.secret_key_encrypted` |
| JWT Token | HMAC-SHA256 | 签名 | ❌ 不能（但可验证） | 浏览器 Cookie / Authorization Header |

## 六、对云端部署的影响

### 6.1 关键问题：主密钥必须一致

**如果主密钥变了，所有已加密的设备密钥全部无法解密。**

举个例子：

```
Day 1: 服务器启动
  → 自动生成 master_key = "AAAA..."
  → 创建客户 Sok Heng，加密设备密钥
  → 数据库存的是用 "AAAA..." 加密的密文

Day 2: 服务器重启
  → 自动生成 master_key = "BBBB..."（不一样了！）
  → Sok Heng 模拟支付 → 平台尝试解密
  → Fernet.decrypt(密文, "BBBB...") → 失败！
  → 返回 secret_key = "" → Token 生成失败
```

**这就是之前种子数据 GPS/MFI 丢失的根本原因。**

### 6.2 正确的云部署配置

**方案 A（推荐）：环境变量注入**

在 Railway / Render 的环境变量面板中设置：

```
SECRET_KEY_MASTER_KEY=nbN-L3VnttBXL-4sB1z9QLIl9nXBvX0SJoTTxZcWdUM=
```

服务器启动时 `os.getenv("SECRET_KEY_MASTER_KEY")` 读取到固定值，无论重启多少次，主密钥始终不变。

**方案 B：Docker Compose**

在 `docker-compose.yml` 中：

```yaml
environment:
  - SECRET_KEY_MASTER_KEY=${SECRET_KEY_MASTER_KEY}
```

然后在 `.env` 文件中设置固定值。`.env` 不提交到 Git（已在 `.gitignore` 中）。

**方案 C：本地开发**

首次启动自动生成密钥并写入 `.env`。后续启动从 `.env` 读取，保持一致。

### 6.3 生成一个永久主密钥

```bash
python3 -c "import base64, os; print(base64.urlsafe_b64encode(os.urandom(32)).decode())"
```

把这个输出配置到云端环境变量，永久不变。

### 6.4 JWT 密钥同理

`JWT_SECRET_KEY` 也建议在云端设置固定值：

```bash
python3 -c "import secrets; print(secrets.token_hex(32))"
```

## 七、故障排查指南

### 问题 1：支付时报"设备密钥无效"或 Token 生成失败

**诊断步骤**：

```bash
# 1. 检查主密钥是否一致
cat .env | grep SECRET_KEY_MASTER_KEY

# 2. 查看服务器是否加载了相同的密钥
# 启动日志中搜索 "SECRET_KEY_MASTER_KEY"

# 3. 查看客户数据
source venv/bin/activate && python3 -c "
import asyncio
from app.database import AsyncSessionLocal
from app.models import Customer
from app.security import decrypt_secret, init_fernet
from sqlalchemy import select

init_fernet()  # 用当前密钥初始化

async def check():
    async with AsyncSessionLocal() as db:
        result = await db.execute(select(Customer))
        for c in result.scalars().all():
            key = decrypt_secret(c.secret_key_encrypted) if c.secret_key_encrypted else None
            status = '✅' if key else '❌ 解密失败'
            print(f'{c.name}: {status}')

asyncio.run(check())
"
```

如果输出全是 `❌ 解密失败`，说明主密钥不匹配。需要：
1. 用一致的主密钥重新加载种子数据
2. 或者找到之前用的主密钥并配置到当前环境

### 问题 2：云端部署后数据全乱了

**原因**：部署时没有配置固定的 `SECRET_KEY_MASTER_KEY`，每次重新部署生成新密钥。

**解决**：在 Railway/Render 环境变量面板中设置固定的主密钥，然后重新运行种子脚本。

### 问题 3：新增客户密码怎么设置

管理员密码使用 bcrypt 哈希。生成方法：

```bash
python3 -c "import bcrypt; print(bcrypt.hashpw(b'你的密码', bcrypt.gensalt()).decode())"
```

得到的哈希值设置到 `ADMIN_PASSWORD_HASH` 环境变量。不设则使用默认密码 `admin123`。

## 八、总结

```
                    ┌──────────────────────────┐
                    │   SECRET_KEY_MASTER_KEY  │ ← 全局唯一，必须固定
                    │   (Fernet 主密钥)         │
                    └────────────┬─────────────┘
                                 │
              ┌──────────────────┼──────────────────┐
              ▼                  ▼                  ▼
        customers          customers          customers
        secret_key        secret_key         secret_key
        (密文1)           (密文2)            (密文3)
              │                  │                  │
              └──────────────────┴──────────────────┘
                                 │
                    主密钥正确 → 全部可解密 ✅
                    主密钥变化 → 全部废掉 ❌
```

**记住一句话**：`SECRET_KEY_MASTER_KEY` 一旦用于加密数据，就**永远不能变**。变了就等于丢掉所有设备钥匙，所有已创建的客户数据全部作废。云端部署时务必通过环境变量注入固定值。
